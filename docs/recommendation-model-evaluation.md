# ALS 模型与融合推荐评估

[返回 README](../README.md) · [模型训练与部署](recommendation-models.md) · [算法说明](recommendation.md)

2026-10-14，本机 Java 21 执行 `AlsEvaluationTest`。完整输出：[验证集 JSON](recommendation-model-validation.json)、[测试集 JSON](recommendation-model-test.json)。它们记录数据摘要、抽样用户、切分时间、参数、指标及配对 bootstrap 区间。原始数据不提交。

## 结论

采用 **ALS-WR + 现有混合推荐**，不采用纯 ALS 排序。验证集从 0.45 / 1.5 / 3.0 三个模型权重中选出 0.45；随后冻结参数，在测试阶段重训后评估。相对于现有内容 / 邻域混合推荐，测试集 NDCG@12 提高约 9.84%，Recall@12 提高约 13.99%，Precision@12 从 0.165 升至 0.185；片库覆盖率有所下降。

**热门榜的 NDCG、Precision 和 Recall 仍高于融合方案。** 不能把这次结果描述成胜过所有基线、证明线上满意度提升或恢复了旧 Spark 二进制的原始效果。当前更适合作为可训练、可回退的个性化功能上线并继续观察。

## 数据与实验约束

- MovieLens 1M 本地历史副本：1,000,209 条评分。按全局时间划分约 70% / 10% / 20%；边界同时间戳保留在前段。
- 验证：700,148 条训练评分，100,020 条未来评分。测试：800,168 条训练评分，200,041 条未来评分。所有特征统计、口碑、热门度和邻居只来自训练段。
- 固定 ALS：16 维、15 轮、正则 0.1、种子 42。只在验证段比较三种融合权重，测试结果未用于再次调整权重。rank=1 对照仅改变维度，用于展示低容量 ALS 的局限，不是重跑旧 Spark 项目。
- 每阶段从至少 20 条历史评分、至少 5 条候选内未来高分的用户中，以种子 20261015 抽取最多 100 人。测试候选为 3,662 部训练中出现的电影，排除本人已评分；未来 >=4 星为相关项，取前 12。
- 所有个性化方法使用相同用户、候选、历史和排除规则。邻域召回沿用线上 200 位邻居 / 50,000 条评分限制；新融合直接调用生产排序器，ALS 个人向量也调用实际 fold-in 实现。
- 同一历史数据此前已用于项目其他报告，本轮不是全新的独立数据集。两个时间窗口的用户也可能重叠；不能跨报告直接把指标变化全部归因于算法。

## 测试集结果

| 方法 | Precision@12 | Recall@12 | NDCG@12 | 片库覆盖率 | 类型多样性 |
|---|---:|---:|---:|---:|---:|
| 训练期热门榜 | 0.2167 | 0.05327 | 0.23535 | 3.17% | 0.7847 |
| 原混合推荐 | 0.1650 | 0.04486 | 0.18255 | 5.60% | 0.5604 |
| ALS rank=1 | 0.0050 | 0.00046 | 0.00568 | 1.39% | 0.3784 |
| ALS rank=16 | 0.0950 | 0.02805 | 0.08117 | 5.79% | 0.7342 |
| ALS + 混合，权重 0.45 | **0.1850** | **0.05114** | **0.20051** | **4.94%** | **0.6029** |

NDCG 差值配对 bootstrap：对 100 位用户重采样 2,000 次，95% 区间为 **[0.00801, 0.02825]**（绝对差，不是百分比）。该区间仅反映这批用户的采样不确定性，不包含数据年代、地域、选择偏差或调参过程的不确定性。

16 维 ALS 的评分预测 RMSE 为 **0.86936**（0.5–5 分截断）；覆盖 11,438 条所选用户的未来评分，另有 10 条电影不在训练模型中。良好的 RMSE 不等于良好的 Top-K 排序，纯 ALS 排序结果已说明这一点。没有真实负反馈的未评分电影在离线排名中按未命中处理，因此对长尾存在偏差。

本机该次测试的 ALS 训练核心耗时约 2.04 秒，融合排序平均约 26.04 毫秒。计时不包含文件解析、HTTP、数据库检索或前端渲染；不是请求响应时间或生产并发承诺。完整训练和数据快照写入的后台耗时可能更长。

## 当前片库的可用性与限制

全局模型可学习 3,706 部电影的关联，但当前本机严格映射只有 **90 / 923** 部。其余电影继续使用原混合推荐；至少 3 部已映射评分才启用个人 fold-in。没有伪造对应关系或将历史匿名用户变成本站账号。

上述排序指标使用 MovieLens 的完整训练目录，**不是当前中文片库 90 部映射子集的效果验证**。电影年代、来源、站内行为和候选分布都有差异；3 条评分门槛也未在本实验中评估，因为排序测试要求至少 20 条历史评分。新用户 UI 引导、删除反馈回退、无模型回退、映射完整性通过功能测试验证，冷启动质量仍需独立数据与在线观察。

上线后按活动模型 UUID 查看 [本站推荐观察](recommendation-observation.md) 中的曝光、点击、收藏、评分分组；单纯切换版本前后比较存在时间和用户构成差异，不能称为随机 A/B 因果提升。数据足够后再做随机分流、3 / 5 / 10 条评分稀疏度评估和当前目录的独立时间留出实验。

## 复现

准备 Java 21、Maven 3.9+ 以及已有的 MovieLens 1M 目录。在仓库根目录依次执行，两个阶段不要颠倒：

```sh
export MOVIELENS_DIRECTORY=/absolute/path/to/ml-1m
mvn -f backend/pom.xml -Dtest=AlsEvaluationTest \
  -Dals.evaluation.data="$MOVIELENS_DIRECTORY" \
  -Dals.evaluation.phase=validation test
mvn -f backend/pom.xml -Dtest=AlsEvaluationTest \
  -Dals.evaluation.data="$MOVIELENS_DIRECTORY" \
  -Dals.evaluation.phase=test test
```

输出为 `backend/target/als-validation.json` 与 `als-test.json`。测试阶段读取验证阶段冻结的 selectedWeight；不要修改 JSON 后宣称是同一评估。未设置数据路径时普通构建跳过大数据实验，保留快速数值单测和 HTTP / 浏览器功能回归。

## 方法依据

显式评分 ALS、latent factor 与按用户 / 电影评分数量缩放正则项的 ALS-WR 定义参考 [Apache Spark 官方协同过滤说明](https://spark.apache.org/docs/4.1.1/ml-collaborative-filtering.html)。当前实现是独立 Java Cholesky 求解器，不依赖 Spark，不声明数值结果与 Spark 实现逐位一致。数据说明与使用条件来自 [MovieLens 1M](https://grouplens.org/datasets/movielens/1m/)。
