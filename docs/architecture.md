# 新版结构与决策

用户体验以电影发现 → 详情 → 私人片单 → 评分 → 推荐为主线。用户端与管理员页面共用前端组件；所有用户身份和权限由后端判定。

技术架构、用户功能、管理权限和推荐流程图已嵌入 [项目 README](../README.md#架构与功能图)；数据导入与离线评估图在 [算法文档](recommendation.md#8-评估与复现) 中。五组图的可编辑源文件及更新步骤见 [图表维护说明](diagrams/README.md)。

## 模块边界

- `auth`：身份、注册、公开账号视图及私人资料 / 冷启动偏好；密码哈希永不作为 API 返回值。
- `movie`：查询、资料、相似电影和推荐排序。所有排序字段由服务端固定分支选择。
- `library`：每个用户的想看 / 看过状态、批量操作与独立评分；用户 ID 从登录身份推导。批量操作先校验再事务写入。评分与看过标记同一事务提交。
- `admin`：电影资料管理和聚合统计；角色由服务端强制验证。
- `config`：认证、安全错误响应、管理员初始化和生产环境 SPA 路由。

前端按视图拆分并使用路由懒加载。查询条件保存在 URL，可以分享和返回；详情数据不依赖 Session 内的“当前电影”。Session 只保存认证信息。

## 数据和推荐

电影条目、用户、片单关系、评分独立建表。用户与电影构成片单和评分的联合主键，重复提交使用原子 upsert。删除电影会级联清理对应片单与评分。

参考评分与本站用户评分分开呈现。推荐器对最多 5,000 个候选进行内容偏好、邻域协同过滤和平滑口碑融合，返回最多 12 部电影；默认精选与主动探索分别控制排序。类型和时长是本次硬约束，个人中心偏好是长期加权信号。

特征权重、正负画像、邻居召回上限、冷启动公式、多样性重排、探索条件以及完整评估入口集中维护在 [推荐算法与评估指南](recommendation.md)，避免在多个文档中重复参数。详情相似电影使用类型交集与参考分排序，是独立的非个性化路径。

前端将模式和筛选写入 URL，批次保存在页面内存；下一组把已出现 ID 作为临时排除条件传入，不创建隐藏反馈。刷新、筛选或观影状态变化会重置批次。请求使用 AbortController，防止快速切换条件导致旧结果覆盖新结果。

推荐排除已入片单、已评分和主动隐藏的电影。隐藏可在个人中心恢复。移出片单不会删除评分；删除评分不会删除片单状态。片单 API 返回所有片单或评分涉及的影片元数据，使已移除电影的评分仍可管理；片单页面按状态明确过滤。撤销只在当前页面保留上一次操作，刷新后不保留。统计时长来自当前“看过”电影片长之和，不计重复观看。

V5 只新增 `user_profiles`、`recommendation_feedback` 和评分索引，不改动现有电影、账号及交互数据。评估基线保留在测试目录，真实时间切分指标与复现方式见 [推荐评估](recommendation-evaluation.md)。

## 部署

开发：Vite 代理 `/api` 到 Spring Boot，API 保持同源。H2 文件数据库提供本地持久化。当前开发配置尚未代理扩充目录的 `/images/catalog`；完整 JAR 模式由后端统一提供页面和图片。

发布：Vite 产物进入 Boot JAR 的 `static` 目录，单个 Java 进程提供页面与 API。可配置 MySQL；不依赖旧版 Hadoop、Kafka 或 FastDFS 集群。

详细环境要求、命令、管理员初始化、数据持久化和升级步骤见 [部署与运行指南](deployment.md)，功能执行顺序见 [页面操作](usage.md)。

## 后续边界

1. 将旧库导出成新版目录格式，建立稳定的外部电影 ID 映射；不得直接混用旧 MovieLens ID 和当前演示目录 ID。
2. 当前已完成 MovieLens 离线对照并接入邻域协同过滤；后续需要在本站真实交互上验证，改善长尾覆盖，并将召回与相似度计算移到离线流程。
3. 图片支持本地公开目录海报及管理员填写的 HTTPS URL；尚未接入头像或图片上传服务。
4. 上线前明确数据与图片授权范围，补充登录频率限制、自动备份与可观测性。
5. UI 样式集中于 `frontend/src/style.css`，下一轮随组件成熟拆分为设计 token、布局和组件样式。

## 公开目录导入

`catalog` 模块提供显式启动参数驱动的本地导入，来源字段通过 V4 迁移添加。导入只更新电影资料，不触及账号、片单和用户评分；整批事务保证失败回滚，来源 URL 唯一索引防止重复导入。外部海报从独立数据目录提供，不与数据库文件共用公开静态目录。
